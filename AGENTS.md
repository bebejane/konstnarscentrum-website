# AGENTS.md

Konstnärscentrum website (Swedish). Next.js **Pages Router** (not App Router) + React 18 + TypeScript (non-strict) + Sass + pnpm. CMS is DatoCMS. Deployed on Vercel.

## Commands

- `pnpm dev` — `next dev` + barrel watcher (`components/index.ts` regenerated on component changes) + `graphql-codegen --watch` (regenerates on `.gql` changes)
- `pnpm dev:test` — dev server against the **dev** DatoCMS environment (`DATOCMS_ENVIRONMENT=dev`) + mailing for email previews
- `pnpm dev:emails` — email template previews (separate Next app in `.mailing/`)
- `pnpm build` — runs `prebuild` (regenerates `regions.json` from DatoCMS) then `next build` then `next-sitemap`
- `pnpm lint` — `next lint` (eslint, `next/core-web-vitals`)
- `pnpm codegen` — graphql-codegen (only needed if you edit `graphql/*.gql`)
- `npx tsc --noEmit` — the only real typecheck

## Generated files — never hand-edit

- `components/index.ts` — barrel of all `components/**.tsx` exports, rewritten by `lib/scripts/barrel.js` (`pnpm barrel`; the watcher does this in `pnpm dev`). Add components as default/named exports; never edit the file directly.
- `graphql/index.ts` + `@types/datocms.d.ts` — generated by graphql-codegen from `graphql/*.gql`. Re-run `pnpm codegen` after editing a `.gql` file.
- `regions.json` — generated during `prebuild` by `prebuild.js` (reads DatoCMS roles). Part of routing, but edits are overwritten at build.

## Build does NOT typecheck or lint

`next.config.js` sets `typescript.ignoreBuildErrors` and `eslint.ignoreDuringBuilds` to `true`. A green production build proves nothing about type/lint errors — run `npx tsc --noEmit` and `pnpm lint` yourself after changes.

## Multi-region routing

One site, six regions: `riks` (global), `nord`, `vast`, `mitt`, `ost`, `syd` (see `regions.json`). Every route has both a global form (`pages/`) and a region-prefixed form (`pages/[region]/`); `/riks` rewrites to the root. Pages use `withGlobalProps` (`lib/withGlobalProps.ts`), which injects menu/footer/regions/SEO and resolves the region from the URL. Per-region DatoCMS API tokens are named `GRAPHQL_API_TOKEN_<REGION_UPPER>` (see `lib/region.ts`).

## DatoCMS environments

`.env` is gitignored but present locally and pins `DATOCMS_ENVIRONMENT=dev` (sandbox). `main` is the production environment — only switch to it deliberately. `prebuild`, `lib/client.ts`, and every maintenance script read this var. API routes are gated by Basic Auth (`BASIC_AUTH_USER`/`BASIC_AUTH_PASSWORD`).

## Conventions

- Absolute imports everywhere: `import x from '/lib/...'`, `'/components'`, `'/graphql'` work via tsconfig `paths` + package.json `exports`.
- Pages are co-located `*.tsx` + `*.module.scss`. Global styles: `styles/index.scss` imported once in `pages/_app.tsx`; `mediaqueries` and `fonts` are auto-imported into every SCSS file (via `prependData` in `next.config.js`).
- ISR: `REVALIDATE_TIME=3600` in env; every page returns `revalidate` via `withGlobalProps`.
- `lib/web-paths.ts` maps DatoCMS models to revalidate + web-preview paths. Add new content types here too, and verify with `pnpm run test:webpaths`.

## Tests (custom tsx runner — no jest/vitest)

- `pnpm run test:fortnox` — Fortnox pure-logic unit tests (no network/credentials). `tests/fortnox.ts`.
- `pnpm run test:webpaths` — evaluates revalidate/preview coverage for every DatoCMS model against the dev env. Flags: `--all` (include modular blocks), `--region <slug>`.
- `pnpm run test:emails` — renders email templates.
- `pnpm test` (`tests/test.ts`) is a scratchpad, not a real test.
- Network-touching (need valid Fortnox tokens, `ost` only): `pnpm run testfortnox` (read-only connectivity), `pnpm run testroundtrip -- <email> <year>` (needs `pnpm run syncfortknox` first), `pnpm run syncfortknox`, `pnpm run deleteinvoices`.

## Fortnox invoicing integration

Read `TESTING.md` before touching anything in `lib/fortnox/`, `pages/api/fortnox/`, or the invoice scripts — it documents the dev-only safety rails (`FORTNOX_EMAIL_ALLOWLIST`, `FORTNOX_ENABLED_REGIONS=['ost']`), the OAuth refresh-token rotation (persisted to Vercel KV on prod, `.env` locally), and the manual endpoint smoke tests. Only the `ost` region is enabled; invoices only ever hit dev DatoCMS + the Fortnox sandbox.

## Auth

next-auth (v4) for member accounts at `/konstnar/konto` (`middleware.js` protects it). Auth/param logic lives in `lib/auth/` (`validate.ts` holds Swedish-language password/email rules). There is no CI; deploy happens via Vercel + `vercel.json` crons.
